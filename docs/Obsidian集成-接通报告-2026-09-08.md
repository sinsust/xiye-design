## 三、代码改动

### 1. 新增 `instrumentation.ts`（根因：watcher 无启动钩子）

此前 `startObsidianWatch()` 只在 API handler 内调用，dev server 每次重启监听即丢失。

```ts
export async function register(): Promise<void> {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  if (process.env.OBSIDIAN_AUTOSTART === "0") return;
  try {
    const { startObsidianWatch } = await import("@/lib/obsidian-watch");
    const res = await startObsidianWatch();
    ...
  } catch (err) { /* 绝不阻断 server 启动 */ }
}
```

实测日志：`[instrumentation] obsidian watch started: 1 vault(s)`
关闭开关：`OBSIDIAN_AUTOSTART=0`（线上部署建议关闭）

### 2. `lib/obsidian-watch.ts` 加固

| 改动 | 原因 |
|---|---|
| 单例状态迁 `globalThis` | HMR 反复求值模块导致句柄泄漏、重复监听 |
| 新增 `handler` 间接层 | dev 改代码后旧 watcher 仍执行旧闭包 → **改了没效果**；改为回调用 `state().handler`，模块重载即刷新 |
| 多配置失败改 `continue` | 原实现任一失败即整体 `return`，且已建 watcher 未清理 |
| 新增轮询兜底（默认 60s） | Windows `fs.watch(recursive:true)` 对深层目录/原子写会漏报 |
| `alignFileName` 返回最终路径 | 重命名后需回写 `obsidianNoteId`/`relPath` |

轮询设计：首次快照只记 mtime 不回放（避免启动风暴），之后仅处理 mtime 变大的文件；`OBSIDIAN_POLL_MS` 可调（最小 10s）。

### 3. `lib/brain-db.ts` 补齐溯源字段

`NewBrainNote` / `UpdateBrainNote` 新增 `obsidianVault` / `obsidianRelPath` / `obsidianNoteId` / `obsidianSyncedAt`，insert 与 update 均落库。

## 四、审计未发现、实施中修掉的 3 个真实缺陷

| # | 缺陷 | 影响 | 修法 |
|---|---|---|---|
| 1 | **列表 select 漏列**（`listBrainNotes` / `listBrainNotesPaginated` / `listByIds` 三处显式 `.select({})` 未含 obsidian 四列） | 列表返回的笔记溯源字段**恒为 null** —— UI 无法标记「已同步到 Obsidian」，回写定位信息丢失 | 三处 select 补列 |
| 2 | **导入不写溯源字段** | `obsidian-sync.removeOne` 的 `if (!note.obsidianVault \|\| !note.obsidianNoteId) return` 直接短路 → 从 vault 导入的笔记在 xiye 侧更新/删除**不会回写 vault** | `processFile` 的 insert/update 均写入四字段 |
| 3 | **主键冲突** | 历史数据 `obsidian_note_id` 为空 → 查不到 → 走 insert 撞主键（`Key (id)=(ob-...) already exists`），整条同步失败 | 双重查找（先 `obsidian_note_id` 列，再按主键 id 兜底）+ insert 唯一冲突降级为 update |

## 五、验证方法（可复用）

1. **沙箱限制**：新起 node 进程直连 Supabase（6543）会 `CONNECT_TIMEOUT` 并被 SIGTERM，但 dev server 自身连接正常 → 改用**临时 API 路由 + `curl localhost`** 间接验证。
   ⚠️ 坑：`app/api/__xxx` 双下划线目录**不注册路由**，需改名（实际用 `obsidian-probe`）。
2. **诊断"同步没生效"**：优先对比**文件 mtime vs `note.updatedAt`**——`processFile` 用 `mtimeMs <= updatedAt` 判定过期后**静默 return，无任何日志**。
3. 验证完成后临时路由、测试 md、测试笔记、脚本**全部删除**。
