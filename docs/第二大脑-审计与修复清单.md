## 一、P0（阻断级）

### P0-1 消除「AI 整理失败 → 只能重新生成」的死胡同
- **服务端加固** `lib/brain-db.ts`：`insertBrainProcessingPlan` 把「插入」与「读回」解耦——插入成功后即使读回失败也返回带 id 的最小 plan，不再把成功插入误判为 null / 重复插入。
- **API 失败回传真实 body** `lib/api-handlers/brain/organize.ts`：计划落库失败时，500 响应仍带上 AI 已算出的真实 `body`，前端不再得到纯 `slice(0,120)` 节选。
- **前端逃生通道** `components/second-brain.tsx` + 新接口 `lib/api-handlers/brain/organize-save.ts`：
  - `organize()` 失败时优先用真实 body 填充并进入「直接保存」模式（`wNoPlan`）。
  - 「采纳并入库」在无 plan 时不再禁用；改走 `POST /api/brain/organize-save`，复用统一写入服务，内容永远可保存。
  - 提示文案如实更新，不再谎称「已用基础整理兜底」。
- 新路由已注册进 catch-all 分发器：`app/api/brain/[[...path]]/route.ts`（`organize-save`）。

### P0-2 版本时间线「点击可切换」真实生效
- `components/brain/note-card.tsx`：版本圆点改为可点击按钮（`stopPropagation`），点击即在本卡查看该版本内容并高亮；新增「正在查看 vX」提示 + 「返回最新」；文案由误导性的「点击卡片名可切换」改为如实描述。

## 二、数据库补齐（本迁移脚本）

live Supabase 原本只有 24 张表，`lib/db/schema.pg.ts` 定义了 32 张。缺失的 8 张会导致**联想相似 / 关系建议 / 学习复习 / 周报 / 任务结果 / 过期整理审计 / 流程幂等**等功能 500 或静默失败，也踩过「笔记无法入库」的表（`archived_at` 缺失）。
`scripts/pg-create-missing-tables.sql` 补齐：`brain_similar_pairs`、`brain_relations`、`brain_curation_log`、`brain_task_outcomes`、`brain_weekly_reviews`、`brain_learning_reviews`、`brain_learning_review_events`、`flow_op_ledger`。
**复核：schema 32/32 = live 32/32，缺失表 0、缺失列 0。**

## 三、P1（体验/流程）

- **「整理笔记 → 记一笔」术语统一**：策略/代码/看板/笔记列表 4 处空状态文案 + 2 处注释统一到「记一笔」。
- **「摘要 / 行动点」去重**：顶部 summary 标签改「摘要」，placeholder 指引行动点去下方「行动项」编辑，行为不变。
- **首页 / 概览 / 收件箱职责收敛** `components/dashboard/TodayAssistantPanel.tsx`：
  - 删除首页「待处理收件箱」预告块，收件箱唯一入口收敛为抽屉 + nav 徽标。
  - 新增「更多今日关注」手风琴（默认折起），收纳 复习/快到期/项目风险/恢复草稿；首页由约 10 块摊平收敛为核心层结构。
- **卡片展开后纵向爆炸收敛** `components/brain/note-card.tsx`：展开区收敛为「原文 + 版本线 + 升级」主结构；「智能分析」「关联」按需手风琴化，缩短单卡高度并减少并发请求。
- **项目「详情入口」伪可点** `ProjectWorkbench.tsx`：去掉笔记/提醒/看板假箭头、改 `cursor-default` + `title` 指明确切去处。
- **看板状态切换提示**：`task-card` 状态按钮本已有 `title`/`aria`；看板刻意不用拖拽（设计决定），维持现状。
- **curate「重新扫描」按卡收敛** `lib/brain-curate.ts` + `lib/api-handlers/brain/curate.ts` + `components/brain/CuratePanel.tsx`：`scanSimilarNotes` / `proposeRelations` 增加可选 `noteId`，单卡重扫从全库 O(N²) 降为 O(N) 单卡。
